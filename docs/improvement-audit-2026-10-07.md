# Pocket Prairie — fixes and improvement todo list

Reviewed October 7, 2026 against **0.9.61**, commit **39f8bf8**. This is an audit and proposed backlog; no application behavior was changed.

**Local implementation update, October 8, 2026:** plant additions N01–N05 are now implemented. Their original problem, rationale and proposed action remain below; [source notes and planning limits](plant-data/audit-additions.md) document the new records. This does not mark other audit work or a release complete.

Three focused reviewers assisted: botanical data/catalog, plant visual morphology, and landscape tools/UX. Findings were checked against the current implementation rather than treating old roadmap entries as unfinished work.

**Priority:** P1 = address first because work can be lost or editing can produce invalid results; P2 = worthwhile correctness/usability improvement; P3 = optional expansion or polish. Priority does not mean every proposal must be built.

**Evidence:** Browser = reproduced in an isolated real browser; Logic = reproduced against the real modules in the Node sandbox; Code = verified implementation limitation; Review = further assessment needed; Proposal = optional feature. A code limitation is not proof of a visible defect on a physical phone.

## Start here

Fix F01–F11 before adding more landscape objects: these cover save conflicts, selection integrity and inconsistent placement rules. Then fix the small broken controls F12–F16 and discovery issues U01–U04. Correct the known plant identities and guidance gaps D01–D04 before a broad catalog expansion. Performance work should start with the specific avoidable work in P01–P02 and fresh device measurements, not a renderer rewrite.

## What does not need rebuilding

- **Plant quantity alone:** 635 base records and 487 nested choices already offer substantial breadth. Focus on exact identity, local fit, distinctive form and missing roles.
- **Basic landscape systems:** fences/gates, pergolas, trellises/arches, seating, containers, fountains/birdbaths, grading, retaining walls and site footprints already exist. Fix their editing integration first.
- **Decking, composite, stepping stones, uplights and step lights:** already present. Their discovery/labeling is the issue.
- **Core planner tools:** matrix planting, fill, pick, move/copy/rotate/erase selection, plant replacement, bloom calendar, ruler, site-photo calibration and planting schemes already exist.
- **A mandatory starting house or restored avatar/story/multiplayer:** contrary to the current design-first scope. Blank ordinary plots are intentional.
- **Woody sizing from scratch:** shared real-size helpers, explicit woody heights, mature previews, canopy overlays and soft spacing warnings are implemented. Keep display size separate from placement rules.
- **Broad renderer makeovers:** low/dwarf conifers, differentiated ferns, weeping/columnar trees and the recent mound/bulb/native-perennial passes already have specialized shared grammar. Use targeted comparisons rather than repeat those passes.
- **Shrub hard exclusion zones:** restoring them would undo the current intentional underplanting policy. Fix accidental solid-object collisions without prohibiting planting beneath shrub canopies.
- **Every repeated botanical name:** some are intentional shape/layer aliases. Do not delete them indiscriminately.
- **Blanket North American flags for every lady fern, ostrich fern or pasqueflower:** modern taxonomic splits matter; correct exact choices with sources.
- **Autosave/offline/update rewrites:** the ordinary workflows pass current browser tests. Address the specific cross-tab and fault-handling gaps instead.
- **Removing wind, disabling image smoothing or increasing every plant's detail:** previous rendering work documents rejected quality/performance tradeoffs. Re-measure the actual problem first.
- **Hydrology, watering or plant-death simulation:** optional scope expansion, not necessary to correct the current planner.
